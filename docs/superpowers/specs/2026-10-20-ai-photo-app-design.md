# AI 识图P图 App — 设计文档

- 日期：2026-10-20
- 状态：已确认（需求沟通完成）
- 下一阶段：实现计划（writing-plans）

## 1. 背景与目标

面向普通个人用户的手机相册 AI 工具：用自然语言批量找照片、批量修照片。核心价值：

1. **对话式检索**：说"找去年海边的日落照片"，本地语义匹配直接出结果，全程离线。
2. **对话式编辑**：选中图片、描述需求（"背景换成海边""去掉路人"），云端生成式模型批量处理。
3. **零门槛批量**：上传断点续传、失败自动重传，多图任务队列化。

### 成功标准（一期）

- 安卓 APK 与鸿蒙 NEXT HAP 均可安装运行核心检索与美化功能。
- 万张级相册导入后，检索响应 < 2 秒（端侧）。
- 断网/杀进程后重新打开，上传任务从断点自动继续。

## 2. 已确认的需求决策

| 决策项 | 结论 |
|---|---|
| 目标用户 | 普通个人用户（相册管理场景） |
| 平台 | 安卓 + 纯血鸿蒙 NEXT 双端 |
| 技术路线 | **Flutter**（华为官方 flutter_flutter 的 ohos 分支），一套 Dart 代码出双端 |
| P图能力范围 | 基础美化 + 生成式编辑 + 抠图分割（不含画质增强/超分） |
| AI 部署 | 端侧为主（检索/美化/抠图优先本地）+ 云端生成（生成式编辑） |
| 图片上传 | 仅编辑任务临时上传，处理完即删；不做云相册备份 |
| 开发方式 | 主要靠 AI 编程（Flutter 生态资料密度是关键选型依据） |
| 商业化 | 暂不考虑，仅架构预留 |

## 3. 整体架构

```
┌─────────────────────────────────────────────┐
│  Flutter 客户端（一套 Dart 代码）              │
│  ├─ 安卓 APK（标准 Flutter）                  │
│  └─ 鸿蒙 HAP（flutter_flutter ohos 分支）     │
│                                              │
│  端侧 AI：图像特征提取 + 向量检索（TFLite 系）   │
└──────────────┬──────────────────────────────┘
               │ HTTPS（仅编辑任务临时上传）
┌──────────────▼──────────────────────────────┐
│  轻量后端（Serverless 函数）                   │
│  ├─ 密钥托管（大模型 API Key 不进客户端）        │
│  ├─ 任务队列 + 状态查询                        │
│  └─ 图片临时存储（处理完即删）                   │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│  云端 AI API：生成式编辑、云端抠图兜底           │
└─────────────────────────────────────────────┘
```

设计原则：

- **隐私优先**：照片数据不出端。检索、美化、抠图全部优先端侧；只有用户主动发起云端编辑时才上传选中图片，成品回存后源图与云端副本即删。
- **密钥安全**：生成式模型 API Key 只存在后端，客户端永远拿不到。
- **可降级**：端侧模型初始化失败时，提示用户并引导走云端能力。

## 4. 功能模块

| 模块 | 说明 | 实现位置 |
|---|---|---|
| 相册导入 | 读系统相册、缩略图、本地媒体库索引 | Flutter + 平台通道 |
| 对话式检索 | 自然语言 → 端侧向量匹配 → 相似度排序展示 | 端侧模型 + 本地向量索引 |
| 对话式编辑 | 指令解析 → 编辑任务 → 云端处理 → 结果回存 | 云端 API + 任务队列 |
| 批量上传 | 分片上传、断点续传、失败重传 | 分片状态存本地 SQLite |
| 主题风格库 | 内置滤镜/风格预设，一键批量套用 | 本地 LUT/参数包 |
| 基础美化 | 滤镜、裁剪、调色（零成本、全离线） | 端侧图像处理 |
| 抠图分割 | 人物/物体分割、批量换背景 | 端侧分割模型优先，云端兜底 |

各模块边界：每个模块独立目录（feature-first），通过明确的接口与核心服务（任务队列、媒体库、向量索引）通信，模块间不直接互相 import。

## 5. 关键流程

### 5.1 检索流程（全离线）

```
导入相册 → 后台逐张提取特征向量 → 存本地向量索引
用户输入自然语言 → 文本向量化 → 余弦相似度匹配 → 排序展示
```

- 特征提取在导入后后台批处理，带进度提示，不阻塞 UI。
- 向量索引方案：一期采用纯 Dart 内存/文件向量索引 + SQLite 存元数据（万张级规模余弦相似度暴力检索已够快，< 2 秒达标），不引入专用向量库；若未来规模超过 10 万张再评估升级。
- 索引损坏可重建：从原图重新批量提取。

### 5.2 编辑流程（云端）

```
选中图片 + 对话描述 → 解析为结构化编辑指令（操作类型+参数）
→ 分片上传原图 → 后端入队 → 云模型处理
→ App 轮询任务状态 → 下载成品 → 保存回相册 → 通知用户
```

- 一条对话可绑定多张图片，形成批量任务队列，逐个执行。
- 指令解析在端侧完成（轻量 LLM 或规则模板），只有执行阶段消耗云端资源。

### 5.3 批量上传（断点续传）

```
文件分片（1–5MB/片）→ 逐片上传 → 每片成功即记录到本地 SQLite
→ 中断（断网/杀进程）后重开，比对已传分片，从断点继续
→ 失败分片指数退避重试（1s/2s/4s/8s/16s，最多 5 次）
→ 网络切换（Wi-Fi↔蜂窝）自动暂停/恢复
→ 全部分片完成 → 服务端合并 → 开始云端处理
```

## 6. 错误处理

| 场景 | 策略 |
|---|---|
| 上传分片失败 | 指数退避重试，最多 5 次；超限标记任务失败，可手动重试 |
| 上传中断网/杀进程 | 本地分片记录保证续传，重开 App 自动恢复任务 |
| 云端编辑任务失败 | 自动重试 2 次；仍失败则任务标记失败并告知用户原因，原图不受影响 |
| 云端任务超时 | 轮询超过阈值（10 分钟）视为失败，走失败处理 |
| 端侧模型加载失败 | 功能入口提示"暂不可用"，可切换云端（若该能力有云端版本） |
| 向量索引损坏 | 检测到异常时自动触发全量重建 |
| 存储空间不足 | 上传/保存前预检查，提前告知用户 |

## 7. 测试策略

- **单元测试**：核心逻辑全覆盖——分片上传状态机、重试退避、指令解析、向量索引读写。
- **集成测试**：后端代理 API（任务创建/状态查询/合并）；用本地 mock 服务测客户端全链路。
- **双端真机验证**：安卓真机 + 鸿蒙 NEXT 真机各一台，重点验证平台通道与端侧模型在两端的实际表现。
- **手动验收清单**：按分期功能列出（断网上传续传、万张相册检索性能、批量编辑队列）。

## 8. 分期交付

### 一期（MVP）：核心价值跑通，零云端成本
- 相册导入 + 本地媒体库
- 对话式检索（端侧向量匹配）
- 基础美化（滤镜、裁剪、调色）
- 双端工程骨架（安卓 + 鸿蒙 HAP 构建通过）

### 二期：云端能力
- 批量上传（分片/断点续传/失败重传）
- 对话式生成式编辑（后端代理 + 任务队列 + 云模型接入）
- 抠图分割（端侧优先，云端兜底）

### 三期：体验完善
- 主题风格库扩充（内置主流主题/风格预设）
- 多语言
- 付费接口预留（仅架构占位，不实现）

## 9. 非目标（本期明确不做）

- 云相册备份/跨设备同步
- 画质增强、超分辨率、老照片修复
- 视频处理
- 社交/分享功能
- 支付与会员体系（仅预留）
- iOS 端

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Flutter ohos 分支成熟度 | 鸿蒙侧插件兼容问题 | 一期先在双端跑通骨架验证；缺口用平台通道写原生桥接；功能做端侧能力检测与降级 |
| 端侧检索模型效果 | "找图不准"损害核心体验 | 一期真机实测调优；预留云端多模态检索作为增强选项（二期评估） |
| 云模型 API 变动/涨价 | 编辑功能可用性 | 后端做供应商适配层，模型可替换 |
| 纯血鸿蒙真机调试环境 | 开发效率 | 确认 DevEco Studio + 真机签名流程先于编码跑通 |

## 11. 附：已否决的备选方案

- **双原生（Kotlin + ArkTS）**：体验最佳但工作量翻倍，与"主要靠 AI 编程"的单人模式不匹配。
- **ArkUI-X**：一份 ArkTS 代码出双端，但社区小、AI 训练资料少，AI 生成质量不可控。
